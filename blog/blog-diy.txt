f:T4151,<h2>为什么要搭博客</h2>
<p>首先，为什么要有自己的博客网站？</p>
<p>看到很多同行都开了自己的博客网站，记录自己的面试准备过程，或者是对前沿技术的心得，博客也是自己技术实力的一种体现。</p>
<p>此外，工作中一定会产生很多自己的思考和沉淀。我自己平常又会写很多笔记，博客就是自己笔记的汇总和提总。</p>
<h2>技术栈选型</h2>
<p>之前在data.ai(已被Sensor Tower收购)上班时，公司用的前端框架就是Next.js, 而在富途和店小秘的业务组都是主要用Vue。对React的理解使用在回国之后慢慢弱了一些，但是后来在进行面试准备的时候发现一线大厂更偏向React。所以为了保持对技术栈的熟悉，我决定自己的博客还是要用Next.js来写。</p>

<h2>0813-代码块高亮和样式更新</h2>
<p>最近又把博客文章的 Markdown 渲染链路升级了一次，主要是为了解决 3 个比较明显的问题：</p>
<ol>
<li>代码块虽然能识别出来，但没有语法高亮</li>
<li>长代码行默认只能横向滚动，阅读体验一般</li>
<li>行内 <span data-rehype-pretty-code-figure=""><code data-language="text" data-theme="github-light github-dark"><span data-line=""><span>code</span></span></code></span> 只有很轻的默认样式，不够醒目</li>
</ol>
<p>之前的实现是 <span data-rehype-pretty-code-figure=""><code data-language="text" data-theme="github-light github-dark"><span data-line=""><span>remark + remark-html</span></span></code></span>，它的优点是简单，能很快把 Markdown 变成 HTML。但是它更像“先把文章显示出来”，对于技术博客常见的代码高亮、代码块换行和行内代码样式，就需要继续补能力。</p>
<h3>这次新增的依赖</h3>
<ul>
<li><span data-rehype-pretty-code-figure=""><code data-language="text" data-theme="github-light github-dark"><span data-line=""><span>remark-gfm</span></span></code></span>
<ul>
<li>让 Markdown 支持 GitHub 风格语法，比如表格、任务列表、删除线等</li>
</ul>
</li>
<li><span data-rehype-pretty-code-figure=""><code data-language="text" data-theme="github-light github-dark"><span data-line=""><span>remark-rehype</span></span></code></span>
<ul>
<li>把 Markdown AST 转成 HTML AST，方便后续继续接入 rehype 生态插件</li>
</ul>
</li>
<li><span data-rehype-pretty-code-figure=""><code data-language="text" data-theme="github-light github-dark"><span data-line=""><span>rehype-pretty-code</span></span></code></span>
<ul>
<li>负责代码块和行内代码的语法高亮，底层使用 Shiki 风格的高亮能力</li>
</ul>
</li>
<li><span data-rehype-pretty-code-figure=""><code data-language="text" data-theme="github-light github-dark"><span data-line=""><span>rehype-stringify</span></span></code></span>
<ul>
<li>把处理完的 HTML AST 再转回 HTML 字符串，继续兼容我现在的博客渲染方式</li>
</ul>
</li>
</ul>
<h3>这次是怎么改的</h3>
<p>新的正文处理链路变成了：</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="ts" data-theme="github-light github-dark"><code data-language="ts" data-theme="github-light github-dark" style="display: grid;"><span data-line=""><span style="--shiki-light:#6F42C1;--shiki-dark:#B392F0">remark</span><span style="--shiki-light:#24292E;--shiki-dark:#E1E4E8">()</span></span>
<span data-line=""><span style="--shiki-light:#24292E;--shiki-dark:#E1E4E8">  .</span><span style="--shiki-light:#6F42C1;--shiki-dark:#B392F0">use</span><span style="--shiki-light:#24292E;--shiki-dark:#E1E4E8">(normalizeMarkdownCodeLanguages)</span></span>
<span data-line=""><span style="--shiki-light:#24292E;--shiki-dark:#E1E4E8">  .</span><span style="--shiki-light:#6F42C1;--shiki-dark:#B392F0">use</span><span style="--shiki-light:#24292E;--shiki-dark:#E1E4E8">(remarkGfm)</span></span>
<span data-line=""><span style="--shiki-light:#24292E;--shiki-dark:#E1E4E8">  .</span><span style="--shiki-light:#6F42C1;--shiki-dark:#B392F0">use</span><span style="--shiki-light:#24292E;--shiki-dark:#E1E4E8">(remarkRehype)</span></span>
<span data-line=""><span style="--shiki-light:#24292E;--shiki-dark:#E1E4E8">  .</span><span style="--shiki-light:#6F42C1;--shiki-dark:#B392F0">use</span><span style="--shiki-light:#24292E;--shiki-dark:#E1E4E8">(rehypePrettyCode, prettyCodeOptions)</span></span>
<span data-line=""><span style="--shiki-light:#24292E;--shiki-dark:#E1E4E8">  .</span><span style="--shiki-light:#6F42C1;--shiki-dark:#B392F0">use</span><span style="--shiki-light:#24292E;--shiki-dark:#E1E4E8">(rehypeStringify)</span></span></code></pre></figure>
<p>这里有两个比较关键的技术点。</p>
<p><strong>1. 在高亮前先规范代码块语言名</strong></p>
<p>我后来排查时发现，新文章里有些代码块写的是 <span data-rehype-pretty-code-figure=""><code data-language="text" data-theme="github-light github-dark"><span data-line=""><span>```JavaScript</span></span></code></span>，而不是更常见的 <span data-rehype-pretty-code-figure=""><code data-language="text" data-theme="github-light github-dark"><span data-line=""><span>javascript</span></span></code></span> / <span data-rehype-pretty-code-figure=""><code data-language="text" data-theme="github-light github-dark"><span data-line=""><span>js</span></span></code></span>。<br>
如果语言名没有被高亮器识别，代码块虽然还是 <span data-rehype-pretty-code-figure=""><code data-language="text" data-theme="github-light github-dark"><span data-line=""><span>&#x3C;pre>&#x3C;code></span></span></code></span>，但里面只会是普通文本，不会生成真正的彩色 token。</p>
<p>所以我在渲染链路里先加了一步 <span data-rehype-pretty-code-figure=""><code data-language="text" data-theme="github-light github-dark"><span data-line=""><span>normalizeMarkdownCodeLanguages</span></span></code></span>，把 fenced code block 的语言名统一转成小写。这样旧文章和新文章都能兼容，不需要回头手动逐篇修改。</p>
<p><strong>2. 高亮和样式是两层职责</strong></p>
<p>这次改动里我更明显地理解了：</p>
<ul>
<li>高亮插件负责把代码切成 token，并输出带颜色变量的 HTML 结构</li>
<li>CSS 负责代码块外观，比如背景、圆角、边框、折行方式，以及行内 <span data-rehype-pretty-code-figure=""><code data-language="text" data-theme="github-light github-dark"><span data-line=""><span>code</span></span></code></span> 的视觉样式</li>
</ul>
<p>也就是说，代码高亮不是“装了插件就自动全部完成”，中间其实还是会落到浏览器能理解的 HTML + CSS 上。</p>
<h3>CSS 这次补了什么</h3>
<p>除了高亮插件，我还在 <span data-rehype-pretty-code-figure=""><code data-language="text" data-theme="github-light github-dark"><span data-line=""><span>globals.css</span></span></code></span> 里补了一层代码块样式，重点包括：</p>
<ul>
<li>给代码块增加背景、边框和圆角</li>
<li>用 <span data-rehype-pretty-code-figure=""><code data-language="text" data-theme="github-light github-dark"><span data-line=""><span>white-space: pre-wrap</span></span></code></span> 和 <span data-rehype-pretty-code-figure=""><code data-language="text" data-theme="github-light github-dark"><span data-line=""><span>overflow-wrap: anywhere</span></span></code></span> 让长代码行可以自动换行</li>
<li>给行内 <span data-rehype-pretty-code-figure=""><code data-language="text" data-theme="github-light github-dark"><span data-line=""><span>code</span></span></code></span> 增加更清晰的背景和内边距</li>
<li>根据明暗模式，分别读取 <span data-rehype-pretty-code-figure=""><code data-language="text" data-theme="github-light github-dark"><span data-line=""><span>--shiki-light</span></span></code></span> / <span data-rehype-pretty-code-figure=""><code data-language="text" data-theme="github-light github-dark"><span data-line=""><span>--shiki-dark</span></span></code></span> 变量来显示高亮颜色</li>
</ul>
